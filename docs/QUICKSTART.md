# First run with FactCircuit v0.3.2

## 1. Install the fixed release

Follow the macOS/Linux or Windows commands in the [README](../README.md#quick-start).
Use Python 3.11 or newer. Creating a virtual environment keeps the installation
separate from your other projects; activation is optional when using its Python
executable explicitly. On macOS, do not use the old system Python.

The GitHub release contains source archives and an installable core wheel. The
source checkout includes the model experiments, their inputs, and setup scripts.
The wheel includes the offline CLI and adapter API; experiments run from source.
There is no requirement to obtain a PyPI package or API key.

## 2. Run the complete offline example

```bash
.venv/bin/python -m factcircuit quickstart --output runs/first-run
```

On Windows, replace `.venv/bin/python` with `.venv\Scripts\python.exe`.
This command works outside the source directory too, using an installed wheel.

The fictional claim is “Northstar has already cut 30% of staff.” The loop follows
a headline to a dispatch and meeting minutes, requests a correction, and learns
that the percentage described a proposed budget ceiling. A deterministic fixture
supplies semantic annotations; no language model interprets this example.

| Output file | What to inspect |
| --- | --- |
| `SUMMARY.md` | Readable explanation and outcome |
| `inputs.json` | Frozen claim, evidence snapshots, timestamps and retrieval order |
| `config.json` | Exact budgets used in this run |
| `trace.json` | Source spans, lineage, reanalysis history, errors and final status |

With the default config, `trace.json` contains:

```json
{
  "fact_status": "contradicted",
  "provenance_status": "original_material_located",
  "stop_reason": "complete",
  "assessment_valid": true,
  "evaluation_mode": "synthetic_annotated_replay",
  "model_api_calls": 0,
  "new_model_inference": false
}
```

There are 3 retrieval rounds and 4 unique material versions. The result above
is a selected-field excerpt, not the full trace. Exit code 0 means the example
executed with a valid assessment; it does not mean every claim is supported.

## 3. Change the resource configuration

The complete example config is [quickstart-config.json](../examples/quickstart-config.json):

```json
{
  "max_rounds": 4,
  "max_documents": 12,
  "max_decomposition_calls": 20
}
```

All fields are positive integers. Omitted fields keep the example defaults.
Unknown keys are rejected. This file contains resource settings, not credentials.

```bash
.venv/bin/python -m factcircuit quickstart \
  --config examples/quickstart-config.json --output runs/configured-run
```

For a visible budget experiment, copy the config, change `max_rounds` to `1`, and
run with another output directory. The loop then stops with an unresolved claim
before the correction arrives. Previously written results remain available.

`inputs.json` records this built-in example; editing that output does not redefine
the fixture's adapters. Use the following workflow for your own claim text.

## 4. Run your own claims with a local model

This optional workflow generates fresh model responses. It has separate setup
requirements and does not share the deterministic example's expected outcome.
From the source checkout:

```bash
python3 scripts/configure_local.py
.venv-local/bin/python experiments/local_inference.py \
  --config .local/model.json \
  --inputs examples/local-claim.json \
  --output runs/my-first-model-run
```

On Windows, use `py -3 scripts/configure_local.py`, then replace the inference
executable with `.venv-local\Scripts\python.exe`. Initial setup needs internet,
a compatible llama-cpp-python CPU wheel, and space for the 2.50 GB pinned model
plus dependencies. Fresh inference additionally needs enough RAM for the model
and its context. Linux x86_64/Python 3.12 was used for the earlier local setup;
macOS/Windows local model inference is not covered by the offline CLI CI checks.

Setup writes `.local/model.json` with the model path, verified SHA-256, context
length, thread count, seed, and call timeout. It selects
**Qwen3-4B-Instruct-2507 Q4_K_M**. This is not a local Astra model or an Astra
comparison. Existing GGUF users can supply their own compatible config using
the fields generated by setup. See [local_model.py](../experiments/local_model.py)
for validation. No API credential or cloud fallback is used by this path.

[local-claim.json](../examples/local-claim.json) is a minimal, fictional one-claim
input. Replace its target, timestamped material and IDs to evaluate your own
snapshot evidence. `target.id` identifies the question; `source_version_id`
and each `seed_ids` entry refer to material `version_id` values. `as_of` is the
evidence cutoff. Keep `assessment_mode: "evidence"` when evaluating only the
supplied materials. Never invent availability timestamps for real evidence.
Gold labels are not placed in the model input.

Read `status.json` first, then `results.json`, `*-trace.json` and `*-calls.json`
inside your run directory. `completed` means the run finished, not that a
prediction is correct. `has_errors` or `local_runtime_error` requires inspecting
the recorded error. Each run needs a new output directory. The bundled provider
searches supplied snapshots; it does not search the live web.

For application integration, implement the provider/decomposer/verifier contracts
and call `factcircuit.provenance.run_provenance` as described in
[TRACE_ADAPTER.md](TRACE_ADAPTER.md). For evaluation, keep gold labels in a
separate file and use the [historical benchmark contract](HISTORICAL_2023_BENCHMARK.md).

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Python version is below 3.11 | Install Python 3.11+ and recreate the virtual environment with that interpreter |
| `No module named factcircuit` | Install using the same virtual environment Python used to run the command |
| `output directory already exists` | Choose a new directory such as `runs/second-run`; previous outputs are preserved |
| Invalid or unknown quickstart config field | Use the three integer fields shown above |
| Local model setup cannot find a matching wheel | Check the Python/OS/CPU compatibility reported by pip; the offline quickstart remains available |
| Model checksum mismatch | Use the setup tool's pinned model; do not disable the checksum check |
| Local model timeout or memory error | Inspect status and runtime logs; adjust your configured context/timeout to the machine's resources |

Offline quickstart exit codes: `0` valid execution, `1` invalid assessment,
`2` configuration or file error. A deliberately small budget can validly produce
an unresolved assessment with exit code `0`.

## Reproduce the installation check

```bash
python3 scripts/smoke_first_run.py
```

This builds the wheel, installs it without dependencies in a fresh virtual
environment, runs outside the checkout, and checks the default and limited-budget
outputs plus the compatibility command. CI runs this check on Linux, macOS and
Windows. It performs no model inference and does not measure accuracy.
