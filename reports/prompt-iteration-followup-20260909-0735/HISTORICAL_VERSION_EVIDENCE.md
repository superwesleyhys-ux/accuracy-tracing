# 历史版本证据：现有准入要求的澄清

现有公开规则及日期校验代码**没有要求每份普通原件都具备历史 SHA-256、可信时间戳或截止日前网页存档**。要求是：有可复核的材料支持“所提供的这个来源版本在截止日期前已经公开”，而不只是文献或页面有一个旧日期。缺少历史哈希本身不是拒绝理由；有一个现在计算的哈希，也不是历史公开的证明。

本说明只澄清证据含义，不降低版本、截止日期、精确真假或两个既有后来日期门槛，不准入任何案例，不改写来源，不修改冻结试验。阅读范围仅为公开的 `SOURCE-PROMPT-DECOMPOSITION.md`、`ADMISSION-INTERPRETATION-0520.md`、`ADMISSION-RUNNER-READINESS-0551.md` 和相关日期代码；未读取私有案例、原文或 gold，未联网或调用模型。

`newsverify/provenance.py` 的 `MaterialVersion` 接收版本标识、正文、取件日期、可空的出版日期，以及 `available_at`、`availability_basis`。`_material_eligibility`（182–205 行）要求明确的版本可用时间和非空依据，拒绝晚于 cutoff、晚于取件等不一致情况；它不要求历史哈希，也不会核验依据文字背后的文献。295–297 行明确允许现在取回有证据支持的旧版本。独立来源审阅负责实际版本认定，填入一段依据并通过代码不等于认定已经完成。实时抓取默认只证明取件时可见，见 `newsverify/news_sources.py` 的 `SourceDocument.available_at`，不能自动把旧出版日期复制成历史可用时间。

以下“可充分支持”均指**整套材料经独立审阅后可以支持版本门槛**，不是自动批准；还须检查其适用范围、可信来源及相反版本证据。

| 证据组合 | 对历史版本的判断 |
|---|---|
| 截止日前可靠存档有实际正文或原文件；捕获时间、资源标识及完整上下文能够核对；排除回放时混入当前页面或附件。 | 可支持该已保存版本当时可见。现在保留捕获文件与提取结果并计算哈希即可固定本次使用的副本；不必要求当年的发布者已经公布相同哈希。 |
| 发布者提供可明确识别的原始正式版本（version of record），其版次、卷期页码或文档版本标识与截止日前公开发行记录一致；发布者的版本/修订记录明确关联当前提供的原始文件，另有同期保留副本、存储库记录及内容核对，或同样具体的发行与保存链可复核其正文和限定条件。 | 可支持这是既有原始版本，即使没有公共网页存档或历史摘要值。必须能解释为何这些记录关联的是所提供的正文版本，而非仅同名文献。不是强制要求上述渠道全部齐备，而是要求实际组合补足版本身份、公开时间和内容对应三项。 |
| 有日期和版本标识的机构原件，官方公开登记/发布记录把该原件与一次截止日前公开发布相连；保留文件的内容、页码、附件范围和修订状态可由具体记录或同期副本交叉核对。 | 可支持该公开原件。文件上的签发日期单独只说明文件自称何时形成，不等于何时公开；无需另加“必须采用密码学签名”的门槛。 |
| 同期保留副本与当前提供的原件在完整正文、相关图表/脚注及版本标识上对应；二进制文件不同可具体归因于封装、字体嵌入或非实质元数据，提取与核对记录可复现。 | 可以支持同一来源正文版本；不能声称两个原文件逐字节相同。冻结当前原文件、提取文本及映射，保留差异说明。若差异涉及数值、范围、结论或上下文，则按不同实质版本处理。 |
| 只有旧出版日期、DOI/目录条目、搜索摘要、HTTP 日期或 PDF 创建时间，再加今天取回的可变网页。 | 不充分。它们可定位文献或支持出版事实，不能独自证明今天的正文就是截止日前正文。DOI、正式版本标签或发布者身份本身也不消除版本歧义。 |
| 有存档 URL、索引时间或历史摘要值，但实际原文不可取回，且没有其他能够核对正文的原件。 | 不能证明所需的完整正文及限定条件已恢复。历史摘要值不是正文的替代品；没有它也不妨碍使用其他充分保存链。 |
| 当前页面带有后来更正、撤回横幅或编辑说明；看起来“删掉这块就像旧页面”。 | 不能据此直接认定历史版本。先分别识别原始正文与后来附加层，并寻找能够支持原始正文版本的记录。仅靠看起来可分离或“未发现其他修改”不充分。 |
| 当前版本有实质修订，或修订时间、适用范围、缺页/附件是否影响目标尚不清楚。 | 当前版本不能冒充旧版本。恢复有证据的旧版；在相反版本信息可能改变判断时保留具体不确定性，不以任意日期或补写内容补齐。 |

“确切版本/所提供字节的依据”容易被误读为必须取得截止日前相同二进制摘要。这里应区分三个对象：历史公开的来源版本、现在保存的原文件，以及模型实际收到的提取文本。现在生成的 SHA-256 负责固定后两者的身份和防止登记后替换；历史时间和来源版本的对应则由保存、发行、修订及内容记录支持。文本抽取可以改变换行或编码，因此它本来就不必等同于原 PDF 的二进制字节；但实际给模型的文本、上下文、偏移和抽取方式仍必须明确冻结和核对。不能用“格式不同”解释未经核实的实质改动。

若有后来横幅或撤回附加层，应保存当前原始取件并把该附加层留在私有审阅边界。只有原始正文版本本身得到独立支持时，未来新语料构建才可能采用可复现、明确记录边界的原文提取；不能凭主观删除不利信息来制造一个“历史原件”。正文已有实质修订时，删除横幅不能恢复旧正文。原文和附加层无法可靠分开，或缺失视觉上下文决定命题含义时，继续标为未就绪。这份说明没有授权任何实际提取修改或对旧语料回写。

日期记录应保留原始精度。`retrieved_at` 表示本次实际取得时间；`published_at` 表示能证实的出版时间，可以为空；`available_at` 表示有证据支持的该版本公开时间或保守上界，其依据应明确说明性质。只有日期而无时刻时，不伪造实际钟点；使用事先声明的保守上界，并确认仍在截止日前。现在才获得旧版或现在才完成提取，并不自动使旧版失格；也不能把新提取文件的创建时间伪称为原件公开时间。

一个实用的版本审阅记录应回答：

1. 哪个来源版本、什么正文和限定条件进入输入？原文件与提取文本怎样对应？
2. 哪些具体记录把这一版本连接到截止日前公开发行或可访问状态？哪个日期是事实，哪个只是上界或推断？
3. 已发现的修订、当前附加层、容器差异和缺失内容是什么，是否影响目标及对照公平性？
4. 结论是“版本门槛有依据”“材料表明此版在截止日后才出现”，还是“具体版本问题仍未解决”？保留残余不确定性，不声称绝对密码学证明或穷尽全部历史。

没有必要仅因不存在绝对证明就无限寻找一个当年未生成的哈希。相反，也不能把普通出版元数据与“未见更改”当成肯定的版本保存链。下一次取件应针对尚缺的版本身份、公开时间、正文对应或修订记录之一；其他证据已补足时，不把网页存档当作唯一渠道。

以上澄清不改变 2023 年底以前的输入边界，也不改变既有“正式确认”与“首次公开确立”两项后来日期检查或精确命题真假门槛。来源原始不等于内容真实；历史版本得到支持不等于案例已准入。若某一冻结合同对该轮明确规定了特定文件或哈希，仍须逐字节遵守；本说明不能追溯放宽它。通用依据仅在后续独立审阅和新登记中使用，旧结果保持原样。
