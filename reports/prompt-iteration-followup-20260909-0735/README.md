# 逐次拆解溯源测试：首次取得新的合格事实错误案例

**本轮筛选 2 个新事件，执行 20 次真实请求，独立复核通过 1 个狭义事实错误案例。** 已取得完整的原始发布文本，并核对后来纠正与原文是否针对同一事实。这里的“错误”是具体事实被追溯纠正，不能据此认定故意造假。

这是来源准入结果，尚未产生新的 Astra 对照成绩。新的配对数据、程序验证、登记和实际模型调用是后续步骤。与已有真实事件控制组成两例后，也只能作为小样本试验。

| 检查 | 结果 |
|---|---|
| 新事件 / 外部请求 / 逐次子提示词 | 2 / 20 / 20 |
| 依据前一次回执继续拆解 | 19 条前序关联均保留 |
| 完整历史原文 | 1 份完整的工具返回文本；没有声称取回原始 HTML 或视觉副本 |
| 后来主要认定材料 | 1 份完整通知文本、2 份官方结构化记录及相关表格摘录 |
| 技术错误 | 5 次，原样保留 |
| 其他不完整返回 | 2 次无匹配、1 次重定向到错误资源、1 份乱码或不完整文档，分别记录 |
| 独立准入 | 1 个具体事实错误案例 |
| 新增模型调用 | 0 次 |

独立审阅确认原文版本与完整相关上下文，核对主体、时期、单位、指标、合并范围及追溯纠正依据，排除了单纯换口径、新估计或不同范围比较。正式认定与首次公开确立均满足既定的 2025–2026 年门槛。首次公开时间依据主要文献时间线和有针对性的检查；不声称证明了全网最早的一天或绝对不存在更早材料。

此次首先寻找可核对的历史原件，再推进后来认定和时间线。每次操作前保存新子提示词，并依据实际返回调整。独立观察在首次操作前见到了总计划，15 次网页操作的提示词在所记录的请求开始前被观察到；5 次直接取件有实际执行脚本的先写入、后请求顺序，以及返回完成前的独立观察。全部 20 份提示词均在相应回执完成前被观察到。不能把这些记录等同于网络层证明、全局请求拦截或跨进程原子锁。

登记到最后服务返回约 16 分 24 秒，到本地关闭状态约 16 分 35 秒，均在预设 20 分钟内；请求用满 20 次后停止。冻结的来源状态写的是“待复核”，独立复核文件随后记录通过，两者分别保留各自时点。未改写先前计划、已发出的提示词或旧标签。

本轮澄清了历史版本要求：不强制存在当年的哈希或网页存档，但仍须有证据把具体正文版本与截止日前公开时间对应。只有旧出版日期仍不充分。该澄清在执行途中单独记录了知悉时间，没有伪装成最初登记内容。

107 个本轮文件条目、340 个既有来源文件、9 个既有来源清单以及选定的模型记录通过完整性检查。另核对了 62 份旧公开报告文件。检查范围详见[独立复核](INDEPENDENT_REVIEW_STATUS.json)，不能据此声称检查了所有外部活动。

下一步独立核对新配对语料与私有标签，完成实际测试程序验证后登记，再运行同模型、同证据的固定对照。模型指导词仍采用冻结的 Candidate 2，准确率优先，token 只记录。来源恢复和流程遵守都不等于已经提高真假判断准确率，也没有建立逐次拆解本身的因果收益。
