# 准确率优先：修复与真实对照结果

**目前仍未超过原始 Astra。** 这轮修复了证据传递和表格读取错误，但未提高造假检出率。token 只记录，暂不作为优化目标或方案选择标准。

本轮只使用既有污水研究事件的两个问题：数据真实性（h05）与论文表述核对（h06）。这是一组已经用于开发的案例，共一个独立事件；表述题不是真实数据对照组。没有开展新的留出集测试。

## 真实模型结果

| 检查 | 原始 Astra | Astra + harness |

| 完整、有效的结果 | 2/2 | 2/2 |
| 符合截止时点证据的判断 | 2/2 | 2/2 |

| 失败或无效结果 | 0 | 0 |

两边都正确区分了“论文这样写过”和“测量确实这样发生过”。因此 2/2 的证据判断正确，不代表识破了造假。此次没有显示检出率提升，也不能用一个已见过的事件估计整体准确率。

两边均通过本地 Codex 登录路径调用同一 `gpt-6-astra`，推理设置为 medium；模型推理仍在远端进行。直接对照没有加载 harness skill。两边使用相同历史材料，截止日期为 2023-12-31；测试进程禁用实时检索，并被隔离在答案文件、后来材料和开发记录之外。模型自身已有知识无法被此方法删除。

## 已验证的修复

- **完整文本进入研究阶段。** 以前只传全文前 16,000 字符，现在传入全部 42,771 字符，加上另一个摘录版本，每次研究请求共 44,120 字符。9 次真实研究请求全部核验一致。正式验证器以前已经读取全文，因此这项修复没有增加正式验证可用的独立证据。
- **历史存档日期保留。** 以前投影没有传入存档依据，h06 研究阶段只看到 2026 年抓取日期，因而提出了多余的历史存档需求；现在明确识别已提供的 2020 年存档，研究结果不再提出这个缺口。修复的是证据传递错误，最终答案与对照仍相同。
- **表格数值保持分列。** 以前相邻单元格的 `10` 和 `20` 会被合并成 `1020`；现在保留单元格、空白格和行的边界。这项修复通过软件回归验证，本轮历史文本输入没有经过实时网页提取，不能把它算作本轮真实检出率提升。

研究输入超过 240,000 字符时会明确失败，不再悄悄截断。完整文本只指已提供的文本版本；未提供的图像、附件和原始测量记录仍未被检查。复杂合并单元格和嵌套表格的版式也未被重建。

**验证：259 项完整软件检查通过，另有 7 项实验检查通过。** 实验检查包括隔离、完整证据、错误保留和篡改拒绝。真实运行的 21 次调用、4 个结果和 6 处最终引用均通过独立审计；没有使用付费模型评委。

## 仍然卡住的部分

真实性问题缺少可独立核对的原始记录，以及文中引用却未随该文本提供的完整结果表和图。全文研究现在准确指出了这些缺口；单靠方法陈述不能证明全部测量真实，也不能证明造假。

资料审核还确认，另一既有事件的 25 页附件此前未进入测试。但尚未锁定它确实在 2024 年前公开的具体字节版本，所以本轮没有加入该附件。该事件的较宽范围资料审查被服务内容检查拦截，后续只核查了文件与版本元数据，没有执行图像或实验内容分析。污水研究缺失的附件也未在这次有界检索中找到；这不证明附件不存在。

本次另筛选 8 个新事件，与之前 19 个合计 27 个候选，仍未形成满足时间、具体主张、结果核验和匹配条件的真假对照组。对两条线索继续核查后，虽然解决了一处原始文件读取问题，但仍存在被检验事实不同、截止时点前核验条件不对称、完整历史快照不足等问题；仅放宽“首次公开”与“正式证实”的日期解释也不足以形成合格的一对。候选资料与后来答案继续单独保存；没有因为模型表现或想达到某个分数而修改标签。计数与后续状态见 [SCREENING_STATUS.json](SCREENING_STATUS.json) 和 [FOLLOWUP_STATUS.json](FOLLOWUP_STATUS.json)。

下一轮要证明准确率提升，需要补齐可核验的历史证据和匹配的真实数据对照，再用未参与调试的独立事件测试。判断标准是检出增加，同时误报与无依据的确定性结论不增加。当前这个标准尚未达到。
