# Independent review of the offline scoring component

The component passed source-blind review and all **38 fictional software tests**: 30 implementation tests and eight separately written regression scenarios. There were no failures or errors. This is not a real-news evaluation, evidence admission, new runner integration or proof of superiority. No benchmark model call occurred.

The independent scenarios exercise the previous role-based scoring risk directly: when a real-world claim's future label is true, calling it false creates a false accusation and never false-case detection. A separate pair makes the harness answer false twice: it hits one later falsehood but wrongly rejects the true control, producing no future-accuracy advantage and worse cutoff agreement. Attribution propositions, uncertain answers and successful formal checks after failed research cannot manufacture a primary detection win. Fatal batches retain four planned rows but suppress primary comparison; deleting a bad or unexecuted row rejects.

Code review also requested strict string validation of arm order and an explicit diagnostic for supported/contradicted assertions that disagree with cutoff gold. Both are implemented and covered by tests. A conflicting result is not classified as a settled assertion. Cutoff mismatch is an accounting diagnostic, not an independent semantic assessment. Matching contradicted cutoff gold is likewise agreement with a reviewed label, not a new evidence-validation procedure.

The module reads no sources or gold files and contains no network, model or token-accounting implementation. Its only imports are standard-language annotations and regular expressions. Audit and adjudication flags must still be established by a trusted future caller. The component deliberately cannot certify actual source provenance, private-gold isolation, request integrity, eligible dates, event-family independence or completeness of receipts.

All eight recorded production and frozen inference implementation hashes remain unchanged. The original author validation is preserved as a record of the initial 30-test stage; [independent validation](INDEPENDENT-VALIDATION.json) and [captured test output](INDEPENDENT-TEST-OUTPUT.txt) record the completed 38-test review. The future runner still requires independent case admission, strict commitment binding, isolated worker tests, actual usage accounting and preregistration before inference.
