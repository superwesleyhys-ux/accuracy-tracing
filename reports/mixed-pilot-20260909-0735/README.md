# 真实历史对照：Astra 与 harness 仍打平

**本次真实测试，两边均为 1/2 正确，均未识别出那条后来被纠正的错误主张。Harness 尚未超过原始 Astra。** 15 次模型调用全部成功，完整执行与独立语义复核均已完成。

两个案例来自不同事件：一个有肯定证据的真实事件，一个在 2024 年前公布、于 2025–2026 年公开确立错误的具体事实主张。后者是被追溯纠正的事实，不等于已证明故意造假。输入只采用独立核对的截止日前文本；后来的记录和真假标签隔离保存。两例各有一个实际来源版本，没有为凑数量复制材料。

| 指标 | Astra 单独运行 | Astra + harness |
|---|---:|---:|
| 截止日前证据判分正确 | 1/2（50%） | 1/2（50%） |
| 与后来实际结果一致 | 1/2（50%） | 1/2（50%） |
| 检出后来确认为错误的主张 | 0/1 | 0/1 |
| 把错误主张接受为真 | 1/1 | 1/1 |

| 模型调用 | 2 | 13 |
| 记录到的 token | 37,233 | 250,560 |

具体失败是**把“来源确实这样报道”转成了“现实中的事实已被证实”**。两边都引用了正确的历史原文，也在解释里承认缺少支持底层事实的证据，却仍对更强的现实主张返回“支持”。独立审阅确认，这不是下载失败、伪造引文或调用错误。四个最终回答的引文都准确，但只有两个最终结论支持其原始现实主张；真实事件在两边均判断正确。

原始来源可以证明某项说法从哪里出现，以及当时如何表达。它本身也可能包含错误，不能自动完成真实性验证。本轮找到了可核对的原文，模型仍在证据能支持的范围上判断失误。

两边使用同一个托管 `gpt-6-astra`、medium 推理设置及本地 Codex 登录通道。直接组为固定的一次回答，harness 使用冻结的 Candidate 2 指导词和研究、正式核验流程。双方收到相同的完整历史证据；没有现场搜索或 API 回退。这里的“本地”指调用和编排方式，模型仍在远端运行；排除后来的输入资料不能抹去模型已有知识。

计划在首次调用前登记，四个结果按固定顺序完成，没有挑选性重跑。实际请求先经过完整的输入、输出、引用、设置和哈希审计，之后评分器才读取已冻结的私有标签。独立审阅另核对了全部四个最终结论、23 个模型回答引文对象和 17 个规范化正式证据片段。

每个 harness 案例实际只进行了一次分解和一次正式核验，没有重访或第二轮正式循环。部分可选研究步骤按记录跳过，不能称为已执行。正式轨迹的内部上限由文档数推导，本轮为 7 轮、12 次分解；语料中的轮数和分解配置没有直接控制这一轨迹。外层最多 10 次正式调用、每例最多 24 次 harness 调用及时间限制始终有效，实际执行均低于这些上限。

完整的模型 token 为 287,793；harness 约为直接组的 6.73 倍。这些数值只覆盖可核对的目标模型调用，不含本任务的整理、来源调查、审阅用量或未独立计量的内部 CLI 重试。当前仍以准确率为先，没有进行 token 优化。

下一版指导词提案针对已确认的问题：最终结论必须回答不变的原始主张，不能把较弱的“来源说过”结论转给较强的事实主张；解释中明确留下的必要证据缺口应与最终判断一致。同时保留充分的一手事件证据，不能一律弃答。提案已审阅，但**尚未安装或实测**。即使后续从错误接受改为有依据的“无法确认”，也不能计为识破未来错误；复用本轮案例只能算开发测试。

两例不足以说明普遍准确率，更没有证明持续优势。持续任务保持启用，后续需要测试新指导词，并用更多未参与调参的独立事件确认效果。
