# 每次溯源重新拆解提示词：真实流程测试

**本轮实际执行了 6 次外部请求，保存了 6 份逐次拆解的子提示词及对应请求记录。取回 2 份机构记录 PDF，但目标历史原文仍未恢复，新增合格假例为 0。** 这是溯源流程实测，没有新一轮 Astra 与 harness 模型对照，也不能据此宣称准确率提升。

这次围绕同一个已有事件，分别核验未尝试的原文路径和较早机构记录的项目范围。执行前登记最多 12 次请求、15 分钟；用完有实质区别的已登记路线后，在第 6 次请求结束时提前停止，剩余 6 次未使用。登记到最后响应约 3 分 3 秒，后续整理和复核时间另外计算。

| 实测内容 | 结果 |
|---|---|
| 实际外部请求 | 6 次 |
| 逐次子提示词与执行前哈希承诺 | 各 6 份 |
| 依据实际返回重新细化任务 | 2 次实质任务细化、3 次格式或路线调整；另有 1 次初始拆解 |
| 技术失败 | 1 次，原样保留 |
| 仅取得当前元数据 | 1 次，不计原文恢复 |
| 下载完整的机构公开 PDF 副本 | 2 份，其中 1 份为公开删节版；不代表取得未删节卷宗或所有附件 |
| 完整目标历史原文、已认证的截止日期前原版本 | 均为 0 |
| 完成全部日期门槛、新增准入案例 | 均为 0 |
| 新增基准模型调用 | 0 次 |

四次直接取件使用事先登记的实验取件脚本：先保存不可覆盖的子提示词、独立哈希承诺和已发出状态，再进入网络请求。两次网页工具操作在独立完成的工具步骤中先保存承诺，再执行请求。实际请求和返回分别绑定到尝试编号。最终没有待处理或状态不明的动作。

独立复核支持本轮按规则执行：6 条提示词与回执链全部对应，未见改写已执行提示词、预算重置或重复尝试。执行顺序有两级证据：2 次承诺在记录的工具启动时间前被独立观察到，4 次直接取件由已登记脚本与回执支持。最初计划和首次请求发生在独立观察开始之前，不能声称所有步骤都有独立现场见证。脚本实现了本地顺序执行下的执行者、状态与预算检查，尚不具备身份认证或跨进程原子互斥。

流程分别处理原文恢复和较早记录的项目范围，并记录依据实际返回产生的任务、格式或路线调整；逐项对应关系由独立审阅者核对。最后取得的登记信息没有提供新的原文位置，因此停止，没有为了用满预算原样重试。精确查询与后来事实留在私有记录中，避免进入模型指导词。

两份 PDF 澄清了已公开材料的范围，不能代替缺失的目标原文。删节内容仍是不可见的，不能推断为不存在。文件日期和当前元数据也不能独自证明特定内容在 2024 年前已经公开。

记录核对可以检验本轮是否执行逐次拆解，但没有相同任务下不拆解的对照流程，不能分离拆解本身的因果收益。执行顺序的证据等级、可观察范围和重复执行约束的限制，以[独立复核](INDEPENDENT_REVIEW_STATUS.json)为准；自填时间或结束后的哈希不单独视为历史顺序证明。

42 个本轮来源文件条目、298 个既有来源文件和 8 个既有清单核对一致；两份 PDF 的文字提取可复现。已登记的模型代码与提示词承诺也通过核对。这些是具体清单覆盖范围内的完整性检查，不代表核查了所有可能的外部动作或全部历史输出文件。

本轮改进尚未进入生产 harness 或冻结模型试验。后续发现或恢复来源时继续逐次拆解；当前已用尽的路线只在确切原件或版本出现新获取条件时重开。新的独立事件筛选应优先确认是否有可获取的历史原件，再投入更多对应与日期核验。
